# 信息架构与页面结构

## 一、这套东西解决什么

实验室同事每天上班第一件事：确认我手上用的标准还是不是最新版。
现在靠人肉盯标委会网站、卫健委公告、群里转发的截图——漏一次就是拿旧版出报告。

所以全站只干一件事：**告诉你哪版标准变了、什么时候开始用、下次出报告前核对哪一版。**

## 二、信息架构

```
标准雷达
├── 今日待办（首页）                    ← 每天上班看这个
│   ├── 四个数：今日必处理 / 近7天变更 / 30天内实施 / 已废止待清理
│   ├── 高优提醒（置顶，红边）
│   ├── 倒计时列表（按实施日期排）
│   └── 下一步该做什么（勾选式清单）
│
├── 标准清单                            ← 需要查标准时用
│   └── Tab：全部 / 产品 / 检测 / 生产 / 体系 / 关联
│       └── 标准详情卡
│           ├── 元信息（号/名/状态/日期/替代关系/归口）
│           ├── 变更摘要 + 为什么重要 + 要做什么
│           ├── 版本时间线
│           ├── 官方入口（阅读/下载，按合规规则区分）
│           └── 由本工具触发的提醒记录
│
├── 我的订阅                            ← 减少噪音
│   ├── 按品类勾选（产品/检测理化/检测限量/生产/体系/关联）
│   └── 提醒强度（90天/30天/立即提醒/周报）
│
├── 提醒中心                            ← 处理 + 周报
│   ├── 筛选：全部/高优/中/低/未读
│   └── 周报预览 + 导出 PDF/Excel + 推送
│
└── 管理后台                            ← 配置
    ├── 监控关键词（增删改）
    ├── 检查频率
    ├── 数据源健康
    ├── 抓取日志
    └── 变更历史留痕
```

**页面间关系**：首页是入口，清单是查询，详情是证据，订阅是控噪，提醒中心是处理闭环。

## 四、数据流

```
每天 07:00 定时触发
    ↓
逐个官方源抓元数据（间隔 ≥4h，源间 2s 礼貌等待）
    ↓
与上次快照 diff  ── 同一标准多字段变更 → 合并成一条
    ↓
关键词匹配        ── 不相关直接丢弃，不入库
    ↓
分级 + 生成文案  ── 变了什么 / 为什么重要 / 要做什么
    ↓
去重（30天桶）    ── 同一标准同一事件类型不重复
    ↓
写入 change_events + alerts
    ↓
推送：站内红点（立即） + 邮件（周报，每周一 08:00）
```

## 五、合规设计（贯穿全站）

| 场景 | 处理 |
|---|---|
| 官方支持免费下载（多数 GB 强制性国标） | 按钮写「⬇ 官方下载」，直链官方站点，不镜像文件 |
| 官方仅支持在线阅读（推荐性国标） | 按钮写「官方在线阅读」+ 一句版权提示 |
| 采标 ISO/IEC | 只给阅读入口 + 正版购买渠道说明，无下载按钮 |
| 拿不准官方是否可下载 | **默认只给阅读链接**，不猜下载地址 |
| 团标 | 标「团标-参考性」，不自动升级为强制依据 |
| 征求意见稿 | 状态标「征求意见」，级别降为低，明确写「暂不改动现行文件」 |

后端只存元数据字段，**数据库里没有任何标准正文字段**——这是刻意的，不留可被误用的口子。
