## 零、本轮补上的三件事（接上真实源之后才显现的缺口）

| 补什么 | 为什么必须补 | 结果 |
|---|---|---|
| **标准勘误** | 勘误不改标准号、不改实施日期、不再发公告，只在勘误表里改一句话。**按标准号做 diff 永远发现不了**，而照错误原文做出来的结果是错的 | `num_tn=4`，176 条，23 条进队列 |

## 一、最重要的结论：主力源不是 openstd

我原本按需求把 **openstd.samr.gov.cn**（国家标准全文公开系统）当主源。实测打脸：

| 检索 `GB 10765` | openstd 结果 | sppt 结果 |
|---|---|---|
| 返回条数 | 1 条 | 2 条 |
| 内容 | `GB 10765-1997` 婴儿配方乳粉Ⅰ **状态=废止** | `GB 10765-2021` 现行 + `GB 10765-2010` |
| 有现行产品标准吗 | **没有** | **有** |

**原因**：GB 10765-2021 属**食品安全国家标准**，由国家卫健委 / 国家食品安全风险评估中心发布，
不进标准委的 openstd 库。openstd 里那批是 1994-1997 年的老国标。

**如果只接 openstd，整个系统对婴配实验室基本没用** —— 实验室真正要盯的现行产品标准一条都抓不到。

改为 **`sppt.cfsa.net.cn:8086/db`（食品安全国家标准数据检索平台）作主力源**，实测抓到 141 条，含现行版本。

## 二、实测可用的接口

### 主力源：sppt.cfsa.net.cn:8086

```
POST /db?task=index          # 先建会话，否则接口返回错误页
POST /db?task=indexSearch
     isLength=9999
     num_tn=99               # 99 = 搜索全部
     standard_type=          # 分类码，空 = 全部
     keyword=GB 10765
→ 返回 JSON 数组
```

字段（实测）：

| 字段 | 含义 | 处理 |
|---|---|---|
| `CODE` | 标准号 | 解读材料带尾随逗号，要 `rstrip(",，")` |
| `TITLE` | 标准名称 | **含解读材料**，要按 `TABLENAME` 过滤 |
| `PDATE` | 发布日期 | 直接可用 |
| `SSRQ` | 实施日期 | 解读材料为 `null` |
| `TABLENAME` | 数据表 | `2`=标准文本 `3`=解读材料 `4`=标准勘误 |
| `ID` / `FJ` | 详情与附件标识 | 仅作官方阅读入口，不下载正文 |

分类码（实测自页面 `activeTabs`）：`1022`=污染物、`1023`=食品添加剂 等。

### 三种库（`num_tn` 切换，切换标签页就是改这个值）

同一个接口，按 `num_tn` 拿不同的库 —— **这是整个系统最重要的发现**：

| num_tn | 库 | 实测条数 | 返回字段 |
|---|---|---|---|
| `1` | 最新公告 | 56 | `CODE/TITLE/PDATE/ID`，**CODE 为空**，标准号写在 TITLE 里 |
| `2` | 标准文本 | 1808 | `CODE/TITLE/PDATE/SSRQ/TABLENAME/ID/FJ` |
| `3` | 标准解读 | 111 | 同上，`CODE` 尾随逗号，**不是标准本体要过滤** |
| **`4`** | **标准勘误** | **176** | 见下 |
| `5` / `99` | 全部标准 | 1808 | 同 `2` |

#### 勘误库（`num_tn=4`）—— 对实验室影响最大

```
STANDARD_CODE / STANDARD_NAME   被勘误的标准
CONTENT                          勘误章节（"5.1.3.2" / "表F.2" / "全文"）
CONTENT_BEFORE / CONTENT_AFTER   改前 / 改后原文  ← 天然就是 diff
REASON                           勘误原因
KWSJ                             勘误时间
GUID / STANDARD_GUID             官方记录标识
```

**为什么这个最重要** —— 两条实测实例：

```
GB 8538-2022      定量限 10 mg/L → 0.1 mg/L          方法能力差 100 倍
GB 5009.208-2016  "转移上层有机相" → "转移上层水相"
    原因栏官方自己写着："有机相在下层，原内容与实际操作不符"
    照错误原文操作，做出来的结果就是错的
GB 5009.7-2016    F 系数：对5.1.1为0.8，其余为1     原：对5.1.1,5.1.3,5.1.4为1；5.1.2为0.8
GB 5009.239-2016  氢氧化钾 → 氢氧化钠               滴定液标定对象都换了
```

统计：176 条中「编辑性错误」136 条、「编辑性修改」39 条、实质错误 1 条。
时间跨度 2018-06 至今。

#### 公告库（`num_tn=1`）

标题形如：
> 关于发布《食品安全国家标准 食品中污染物限量》（GB 2762-2025）等32项食品安全国家标准和**2项修改单**的公告（2025年 第6号）

可直接解析出：年度公告号、**标准数量**、**修改单数量**、点名的标准号。
实测最近一份：**2026-08-18「等50项食品安全国家标准和修改单的公告（2026年 第6号）」**。

### 副源：openstd.samr.gov.cn（老国标与作废版本）

```
GET /bzgk/std/std_list
    p.p1=1        # 1=国标 2=行标 3=团标 6=企标
    p.p2=标准号或名称
    p.p5=状态 PUBLISHED/TOBEIMP/REPLACED/WITHDRAWN
    p.p7=时间 0.08=三月 0.25=半年 1=一年 2=两年 3=三年 6=六年
    p.p90=circulation_date  p.p91=desc
→ HTML，table.result_list
```

列序（实测）：`[1]`标准号 `[4]`名称 `[5]`强标/推标 `[6]`状态 `[7]`发布 `[8]`实施

详情页：`GET /bzgk/gb/newGbInfo?hcno=<32位HEX>`，hash 藏在 `onclick="showInfo('...')"`。
**详情页是单列「标签：值」格式，不是两列表格** —— 按全角冒号切分才对。

### 副源二：std.samr.gov.cn（行标/团标入口）

原本以为这个源没法用（检索走 JS 异步），后来在页面的 ajax 线索里找到了未文档化的接口：

```
GET /gb/search/gbQueryPage?searchText=<词>&current=1&size=20
→ {"total":N,"pageNumber":1,"rows":[{...}]}
```

字段：`C_C_NAME` `C_STD_CODE` `STD_NATURE` `STATE` `ISSUE_DATE` `ACT_DATE` `id` `PROJECT_ID`

两个坑：

**1. 字段里内嵌 XML 标签**（解析残留），不清洗标准号会带着标签导致关键词匹配全部失效：
```
C_STD_CODE = "<sacinfo>GB</sacinfo> <sacinfo>10765</sacinfo>-1997"
C_C_NAME   = "<sacinfo>婴幼儿</sacinfo><sacinfo>配方</sacinfo>乳粉"
```

**2. 检索词不能带空格**（实测差异巨大）：
```
"GB 5009"   → 233 条
"GB 5009.5" → 0 条      ← 带空格按短语匹配，命中骤减
"GB5009.5"  → 0 条
"5009.5"    → 11 条
```

好处：它的 `STATE` 字段直接给中文状态（"现行"/"废止"），比 openstd 少一层映射。
还捞出一批婴配特有的老标准：`GB/T 5413.6~5413.25 婴幼儿配方食品和乳粉` 系列
（泛酸、胆碱、磷、碘、氯、肌醇、不溶性膳食纤维、灰分的测定），是历史沿革，值得留档。

## 三、踩到的坑（都已修）

### 1. 官方源自己数据有错

`GB 5009.303-2025` 在 sppt 上名字是：

```
食品安全国家标准 食品中酵母锟斤拷-葡聚糖的测定
```

`β` 变成了 `锟斤拷`。用 utf-8 / gbk / gb18030 三种编码交叉验证，确认是**源站数据缺陷**，
不是我们解码错误。代码里做了本地修正（`_fix_mojibake`），修正记录进抓取日志。

**这类脏数据只能靠日志暴露，不能静默入库。**

### 2. 解读材料混在标准里

搜 `GB 5009.5` 会同时返回标准本身和《…》（GB 5009.5-2025）解读材料。
解读材料不是标准，标准号还带个尾随逗号。已按 `TABLENAME` + 标题关键词双重过滤。

### 3. 首次运行会刷屏

首次建基线时库里 150+ 条全是"新发布"，一次性推给用户等于什么都没说。
已加 `first_run` 判断：**首次只建库不推提醒**，但"90 天内要实施"的倒计时提醒仍然生效——
那是真实待办，必须让用户看到。

### 4. 源之间速度差 10 倍

sppt 单次查询约 2 秒，openstd 每词一个页面请求。
原来统一取 40 个检索词，openstd 那轮跑了 2 分钟没跑完。
已改成**每源独立配额**（`SOURCE_QUERY_LIMIT`）：sppt 给 40，openstd 给 12。

### 5. 本机 SSL 证书链有自签根

公司代理导致官方站点证书链验证失败。`http_client.py` 里做了兜底：
优先读环境变量 `REQUESTS_CA_BUNDLE`，没有才降级。只抓公开元数据，不传凭据。

### 6. 标准号子串匹配会误命中（真 bug）

最初用 `term in std_no` 匹配，结果：

```
订阅「GB 5009.3」（水分）   →  误命中 GB 5009.312（多种真菌毒素）
订阅「GB 5009.9」（还原糖） →  误命中 GB 5009.96（赭曲霉毒素A）
```

这两条在官方库里都真实存在，直接造成提醒噪音。已改为按"前缀+分部号"精确比对
（`_std_no_match`），并补了 10 条单元用例，全部通过。

### 7. 提醒噪音比"抓不到"更致命

第一次真跑，141 条抓回来 7 条提醒，其中 **5 条是真菌毒素检测方法**——
因为 `GB 5009.*` 通配词把整个 5009 系列（124 条）都拖进来了。

这不是"多推了几条无关的"，而是**订阅直接被噪音埋掉**。做了三层处理：

| 层 | 做法 | 效果 |
|---|---|---|
| 源端 | 解读材料、勘误记录按 `TABLENAME` 过滤 | 剔除混入的非标准条目 |
| 匹配端 | 标准号精确匹配，修掉子串误命中 | 5 条真菌毒素不再误命中 |
| 相关端 | `core` / `edge` / `none` 三档权重 | edge 只入库不提醒 |

最终 **7 条 → 2 条**，只剩 GB 25596-2025 与 GB 29922-2025 两个特医通则换版 ——
这才是实验室真正要看的。

`is_relevant` 的三档：
- `full` 精确订阅项命中 → 必提醒
- `core` 营养成分/安全限量/致病菌/婴配专有 → 必提醒
- `edge` 真菌毒素/添加剂/农残 → **只入库，不提醒**（除非它是全新发布）
- `none` 其余 → 静默入库

### 8. 首次运行不能推提醒

第一次建基线，库里 150+ 条全是"新发布"，一次性推给用户等于什么都没说。
已加 `first_run` 判断：**首次只建库**，但 90 天内的倒计时提醒仍生效——那是真实待办。

同时给提醒加了中期档（90~365 天），级别强制降为"中"，不占高优红点。
理由：实操中 138 天后实施的标准实验室也该知情，但不能和 30 天内的混在一起。

### 9. 级别降了，重要性不能跟着降

修完噪音问题后，邮件里出现这么一句：

```
[中] GB 25596-2025  特医通则
  为什么重要：属生产规范 / 体系标准，影响 SOP 与体系文件，但不改判定阈值。
```

**这是错的。** GB 25596 是**特医产品通则**，是产品标准，
只因为距实施还有 164 天被降级成"中"，结果按级别措辞就把它说成了生产规范。

已改为 `_why_by_category()` —— **"为什么重要"按标准类别判定，与最终级别解耦**。
动作清单同样按类别分流：产品标准查注册检验衔接，检测方法做方法验证与数据比对，
生产规范查取样留样，体系标准查证书版本。

### 10. 失败的源要熔断，但不能永久禁用

卫健委 412 拦截后，代码仍按 10/30/90 秒退避重试，**每次白等 85 秒**。
每天都这样等纯属浪费；但因为一次失败就永久停用也不对——风控是会恢复的。

最终方案：连续失败 3 次 → 冷却 24 小时跳过 → 恢复后自动重试。
另加一条：返回 0 条且无历史快照时判定为"未接通"，直接报错而不是假装成功。

实测：熔断触发后 **84 秒 → 1.7 秒**。

```bash
python crawler.py --run --source SRC-03   # 连跑三次后
# [WARNING] [SRC-03] 连续失败 3 次，冷却中（24 小时内跳过）
```

## 六、跑之前必须知道的

### 依赖

```bash
python -m pip install requests lxml
```

本机 pip 走代理会失败（`no matching distribution`），需直连或配企业源。

### 首次运行

```bash
python crawler.py --init-db
python crawler.py --run
```

**第一次只建基线、不推提醒**，这是刻意的。第二次起才有 diff 提醒。

### 单源调试

```bash
python crawler.py --run --source SRC-05
```

### 公司代理 SSL 报错

设根证书路径，不要直接关校验：

```bash
set REQUESTS_CA_BUNDLE=D:\path\corp-proxy-ca.pem
```

## 六、下一步建议（按性价比排）

1. **卫健委 412 绕一下** —— 需要带 Referer + Cookie 会话，可能是简单风控
2. **std.samr 找开放接口** —— 该平台有开放数据服务，比爬 JS 靠谱
3. **GB 5009 系列的通配词** —— `GB 5009.*` 一次拉回整个系列（实测有效），
   建议加"实验室自测项目清单"作为检索词，比关键词表更贴合实际
4. **接 CFSA 标准勘误** —— `TABLENAME=4` 的勘误记录对实验室影响最大
   （限量值勘误 = 之前的判定可能错了），目前只标记未进提醒队列
