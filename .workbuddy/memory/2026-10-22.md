## 踩的坑

### ★ inject_refdata.py 只支持数组值 ★
`inject_datajs` 扫到 `  KEY: [` 后按数组边界替换，遇到 `{` 直接报
`[x] JSA 的值不是数组`。
→ JSA 是嵌套对象，产物改成 **一个元素的对象数组** `[ {...} ]`，页面侧取 `JSA[0]`。
（另一条路：写 `window.STDWATCH_DATA.JSA = {...}` → 报
`SyntaxError: Unexpected token ';'`。）

### ★ 拆分「1=a / 2=b」这类串，两次都踩坑 ★
- 第一次用 `split("/")` → 值里带半角逗号（`4=严重(重伤/中毒)`）被切坏，
  严重度 S 变成 **7 项**。
  → 改用 `re.split(r"(?=\d\s*=)")`，只在「数字=」处切。
- 第二次改风险等级时用正则前瞻 `(?=[^\s/]{2,6}\s*R\s*=)` → 在「低」这种单字后
  也匹配，把「低风险 R=1~4」切成「低」+「风险 R=1~4」，grades 变成 **10 片碎片**。
  → 等级名里没有斜杠，**直接 `split(" / ")` 就够**。
  ★ 教训：能简单就别上正则；上前瞻前先想清楚它会不会在不该匹配的地方匹配。★

### ★ `git checkout data.js` 会冲掉注入结果 ★
调试时用它回滚，结果把刚注入的 guid 链接也冲掉了 →
`GB 5009.5-2025` 的 url 退回首页，测试报「postJump 的 url 带 guid」失败。
→ 改数据后要重新跑 `sync_std_to_proto.py` + `inject_refdata.py`。

### 测试断言的坑（三个都是我的断言写错，不是代码错）
1. 审批区「不含日期」：按「下一个同名 function」切 → jsaSignoff 是最后一个函数，
   切到文件尾，把后面注释里的 2026-10-04 圈进来误报；
   改按「下一个 \nfunction 」也不行 —— 它后面紧跟的是 `const SUBS`。
   → 最终按「下一个顶层声明」切：`/\n(function |const |let |var )/`。
2. 截固定 2600 字符同样会吃到后面的注释。
3. `test_nav_order.js` 还在断言已删的两个旧入口 → 改成断言「已下线」+「JSA 排第一」。

### ★★ 换算踩的坑（每个都查了根因）★★
1. **键名映射**：原料表用简写 `p/f/c`，NUTRIENTS 用全名 `protein/fat/carb`

2. **基准不统一**：国标宏量也是**每 100kJ**，不是每 100g。
   → 每个营养素加 `basis` 字段（per100g / per100kJ / ratio）。
3. **系数 100 倍**：每 100g 成品含某营养素 = 原料每100g值 × kg/1000

4. **mg/μg/g 三种单位**：原料表混用 → 统一走 `convTo100kJ()`
5. **能量方程与宏量方程线性相关** → 最小二乘解出 1e10 量级垃圾
   → 改用坐标下降 + 硬约束
6. **坐标下降陷局部极小**（油脂被优化成 0）→ 缺「调和植物油」这种通用油脂
   → 补进原料库后收敛
